# Feature architecture boundaries

Feature ownership is the first directory below `src/features`. Nested areas
such as `portal/deliverables` and `submissions/evaluation` belong to their
root feature unless and until they receive an explicit top-level contract.

Run the graph report with:

```bash
pnpm architecture:report
```

The report parses production TypeScript and TSX with the TypeScript compiler
API. It includes static imports, re-exports, dynamic imports, and CommonJS
`require` calls. Tests are excluded because their setup dependencies are not
runtime architecture.

## Edge classification

Every cross-feature edge receives one of these mechanically reviewable
classifications:

- **Contract:** the target resolves to a public `index.ts`, `index.tsx`, or
  named index such as `index.client.ts`.
- **Composition:** the source is an application-level coordinator
  (`cfp`, `onboarding`, `data-lifecycle`, `shell`, or `public`) and the target is
  still reached through its public contract. Composition describes why the
  dependency exists; it does not waive the public-entrypoint rule.
- **Violation:** the source reaches a file inside another feature instead of a
  public index, or a server module imports a component, shared UI module, or
  application route.

The complete set of current violations is recorded in
`architecture/feature-boundaries-baseline.json`. This is a debt ledger, not an
allowlist for new design: CI fails for both a new entry and a stale entry, so
each cleanup PR must remove the corresponding baseline line.

## Current graph

The initial AST inventory found 43 dependency directions, 55 direct-import
violations, no server-to-UI/route imports, and one strongly connected group:

```text
auth -> comms -> events -> forms -> organizations -> portal -> submissions
```

The remediation is now at 42 dependency directions, zero direct-import
violations, zero server-to-UI/route imports, and no cyclic feature group. The
`cfp` composition feature owns the former forms/submissions orchestration edge;
shared delivery primitives and the `event-contacts` owner removed the other
back-edges without broadening feature barrels.

The exact direction counts are generated by `pnpm architecture:report`; the
exact source/specifier violations are the reviewed baseline. Keeping generated
facts in those two places avoids a prose graph silently drifting from code.

## Ratchet policy

`pnpm architecture:check` runs in the static CI job and fails when:

- a feature adds a direct import that bypasses another feature's public index;
- a server module begins importing feature UI, shared UI, or a route module;
- the strongly connected feature groups change without an explicit baseline
  update;
- a recorded debt entry becomes stale without being removed from the baseline.

The direct-import and cycle baselines are now empty. Follow-up changes must keep
them empty, move neutral contracts into `src/shared/contracts`, and keep
cross-domain orchestration in explicit composition services.

Syntax-sensitive repository policies are enforced separately by
`pnpm source:check`. That gate parses TypeScript and TSX instead of relying on
text patterns for imports, JSX attributes, environment and storage access,
reviewer-role calls, or inline numeric styles. `pnpm invariants` composes it
with greps that remain appropriate for literal configuration and CSS values.
