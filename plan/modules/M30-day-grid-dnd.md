## Objective
The Day view becomes the live drag-and-drop scheduling surface: a time × room CSS grid where an organizer drags sessions between slots and rooms, resizes by duration, and drags unscheduled sessions in from a panel — with instant client-side conflict outlines and a version-CAS'd server write underneath. When done: dragging a seeded session onto the seeded conflict pair shows a red outline immediately and the Conflicts badge increments; a stale concurrent drag rolls back cleanly with a toast, never silently overwriting another admin's move.

## Step-by-step implementation

1. **Contract-first: grid skeleton with no drag yet.** Build `day-view.tsx` to render `day-tabs.tsx` (tabs for each `eventDayKey` between `event.startsAt` and `event.endsAt` — loop with `addDuration(cursor, 'P1D')`, dedupe via `eventDayKey`, no new `time.ts` function needed) and `day-grid.tsx` showing the selected day's sessions as static (non-draggable) positioned cards, using `props.sessions` filtered to the current day and `props.rooms` as columns. **Done when:** switching `?day=` tabs shows the right day's sessions positioned at roughly the right time, with zero drag interactivity yet — this alone unblocks visual QA before the mutation wiring is done.

2. **`day-view/slots.ts` — pure grid layout math (no React, no server calls).** Given the day's sessions (already day-filtered) and the event timezone, compute:
   - `gridStartMinutes`/`gridEndMinutes`: the earliest session start rounded down to the nearest hour and latest session end rounded up to the nearest hour, in event-tz minutes-since-midnight (via `formatInZone`/`zonedInputToUtc` from `time.ts` — do not do this math in UTC or browser-local time). If the day has zero scheduled sessions, default to `08:00`–`18:00` so the grid isn't zero-height (still usable as a drop target for the first drag-in).
   - `SLOT_MINUTES = 15` — one grid row per 15-minute increment (matches the brief's snap granularity and app-architecture's stated slot size).
   - `minutesToGridRow(minutes)`: converts an event-tz minutes-since-midnight value into a 1-based CSS grid row line index relative to `gridStartMinutes`.
   - Export `MIN_SESSION_DURATION_MINUTES = 15` (PROPOSED — not a literal number in any doc; chosen to equal the slot size so a resized session always spans ≥1 full row and never collapses to zero height).
   **Done when:** a table-driven unit test (a handful of cases, not a full suite — this is UI-adjacent, not S1/S3-tier logic) confirms row math for on-the-hour, on-the-quarter-hour, and an empty-day default range.

3. **Session cards + droppable grid cells.** `session-card.tsx`: positioned via inline style `gridRow: \`${startRow} / ${endRow}\`, gridColumn: roomIndex + 1`, colored by track (reuse the track color chip pattern from M28's list view), shows title + time range + speaker initials. Wrap each card in dnd-kit's `useDraggable({id: session.id, data: {type: 'session', session}})`. `day-grid.tsx` renders one `useDroppable` cell per `(room, 15-min slot)` pair (droppable id encodes `roomId` + slot start minutes) — cells can be visually merged (a single continuous room column) but must exist as discrete droppable targets so drop position resolves to an exact 15-min-aligned time.

4. **`unscheduled-panel.tsx` — the drag source for "drag from tray to schedule."** This module renders its **own** panel (do not reuse or edit ./M28-sessions-crud.md's toolbar-level tray component) listing `props.sessions.filter(s => s.startsAt == null)` for the current event, each wrapped in `useDraggable` with `data: {type: 'unscheduled', session}`. This keeps the entire drag interaction inside one `<DndContext>` this module owns end-to-end, with zero edits to a file M28 owns. **Done when:** the panel lists the seeded unscheduled sessions.

5. **One `<DndContext>` wrapping the grid + the unscheduled panel**, in `day-view.tsx`. `sensors: [useSensor(PointerSensor, { activationConstraint: { distance: 8 } })]` — the 8px movement threshold before a drag activates is what keeps normal touch/mouse page scroll working outside a card (agenda-embeds.md edge case #5 / app-architecture's touch note). `onDragEnd(event)`: resolve the drop target's `roomId` + slot-start-minutes from `event.over.id`; compute `newStartsAt`/`newEndsAt` — for a session dragged from the grid, preserve its original duration (`endsAt - startsAt`) and shift both by the delta to the new start; for a session dragged from the unscheduled panel, use its `session_formats` default duration (fall back to 30 min if the format has none) as the new duration. Convert the event-tz slot time back to a UTC instant via `zonedInputToUtc`.

6. **Resize handles.** `resize-handles.tsx`: two thin `useDraggable` strips (top edge = adjusts `startsAt` only, bottom edge = adjusts `endsAt` only) rendered inside `session-card.tsx`. On drag, compute the pointer's vertical delta in pixels → slot count (row height is a CSS custom property both the grid and the handles read) → round to nearest `SLOT_MINUTES` (snap) → apply to the relevant boundary, **clamped** so the resulting duration is never below `MIN_SESSION_DURATION_MINUTES` and the boundary never crosses the other one. Snap rounding must not silently change duration on drop if the pointer didn't move a full slot — round the *delta*, not the absolute position, so a tiny unintentional jiggle doesn't resize at all (agenda-embeds.md edge case #5).

7. **Optimistic move + CAS.** `hooks/use-move-session.ts`: a TanStack `useMutation` wrapping `POST /api/internal/agenda/sessions/[id]/move`. `onMutate`: cancel in-flight queries for `qk('agenda', eventId, 'sessions')`, snapshot the previous cache value, optimistically patch the dragged session's `startsAt`/`endsAt`/`roomId` in the cache, return the snapshot as mutation context. `onError`: roll back to the snapshot **and** show a toast — if the error is `STALE_WRITE` (409), the toast reads "Schedule changed — reloading the latest version" and the handler also calls `queryClient.invalidateQueries(qk('agenda', eventId, 'sessions'))` to refetch truth (never silently keep showing the stale optimistic position). `onSettled`: always invalidate the sessions query so the server's authoritative row (and its fresh `conflicts` array returned by `moveSession`) becomes the source of truth, superseding any client-computed guess.

8. **Live client-side conflict outlines.** After every optimistic patch (in `onMutate`, before the server responds) AND after the server's authoritative response lands, recompute `detectConflicts(sessions.filter(s => eventDayKey(s.startsAt, tz) === currentDay).map(toScheduledSession).filter(Boolean))` over the in-memory session list for the visible day and store the result in the day-view-local Zustand slice (`use-day-grid-state.ts` — ephemeral, cleared on unmount; this is exactly the "drag ghost / active view / day" category of allowed Zustand state per app-architecture's litmus test, never persisted server truth). `session-card.tsx` reads that slice to render a red outline (error-severity conflicts) or amber outline (warning/track conflicts) when the session id appears in `conflict.a`/`conflict.b`. The badge count on the Conflicts tab (owned by ./M31-agenda-views.md) reads the same server-returned `conflicts` array via the shared `AgendaViewProps`/query cache — do not maintain a second count anywhere.
   **Done when:** dragging a session onto the seeded conflict pair's room+time shows the red outline within one render (no server round trip required for the visual), and once the server confirms, the outline persists (or disappears, if the server's authoritative recompute disagrees with the optimistic guess — rare, but the server response wins).

9. **Touch/mobile smoke.** Manually verify on a phone-width viewport (or Chrome device emulation) at the end of the module: page can still be scrolled vertically outside a session card; a session card is draggable when touched directly; this is a manual check, not a Playwright spec (DnD mechanics are excluded from the automated suite per quality-strategy §3).

## Guardrails
- **Never reimplement conflict math here** — always call M29's `detectConflicts`/`toScheduledSession`; this module only decides *when* to recompute and *how* to render the result.
- **`moveSession` is the only write path this module calls** — it never issues its own DB query or opens a transaction. All CAS/schedule_revision/outbox logic lives in M28; this module's entire job is UI + optimistic cache + rollback.
- **Snap-to-grid must not silently change duration** (agenda-embeds.md edge case #5): rounding the *delta* (not the absolute drop position) during resize is the specific mechanism that prevents a 1px pointer jiggle from resizing a session.
- **Min-duration clamp is enforced client-side for UX AND must be re-validated server-side** — `moveSession`'s zod input schema (M28) already enforces `endsAt > startsAt`; this module's clamp is a UX nicety on top, never the only guard (never trust the client).
- **Timezone**: every pixel-to-time and time-to-pixel conversion goes through `time.ts`'s `zonedInputToUtc`/`formatInZone` — never construct a `Date` from browser-local components. The demo event is `America/Los_Angeles`; an agent testing from a UTC or non-Pacific machine will silently get this wrong without disciplined use of the shared helpers.
- **One `<DndContext>`, owned entirely by this module** — the unscheduled panel used for "drag from tray" lives inside `day-view.tsx`'s own tree specifically so no file owned by M28 needs to be touched. Do not attempt to share a DndContext across the toolbar-level tray and this view; that coupling was deliberately designed out (see Step 4).
- **Rollback must be visually clean, not just "eventually correct"** — the optimistic patch and its rollback both go through the *same* TanStack Query cache entry the read views use, so a failed drag snaps back to exactly where it was, never leaves a ghost card or a duplicate.
- **Non-blocking, per M29's design contract**: this module never prevents a drop because it would conflict — it always persists the move (via `moveSession`, CAS permitting) and only *visualizes* the resulting conflict. Do not add a confirm-dialog or a hard block on dropping onto a conflicting slot.
