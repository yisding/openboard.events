## Objective
The two public, mobile-first, auto-updating pages every judge and every third-party website will actually see: `/e/[slug]/schedule` and `/e/[slug]/speakers`, in the visual spirit of `wf2025.ai.engineer/schedule`. Both read exclusively through `published_sessions_v`/`published_speakers_v` so a draft session or an admin-declined speaker can never leak. When done: anyone with the event slug — no login — can browse the schedule by day, filter by track, search, tap a session for detail, browse the speaker gallery, and everything reflects an organizer edit within 60 seconds. This module is also the foundation ./M33-embed-shells.md wraps for the iframe deliverable, so its component tree must be chrome-agnostic from the start.

## Dependencies
- **Hard (blocks start):** ./M03-db-schema-migrations.md — `published_sessions_v`, `published_speakers_v`, and the raw `session_speakers` table migrated on sb-dev (this module reads views for everything except the session↔speaker bridge, see Step 2). ./M28-sessions-crud.md — real session data exists to read (schema alone isn't enough; the seed's ~15 sessions with 2+ published need to be there). ./M07-r2-storage.md — `/f/[fileId]` public serving live, so headshots resolve to real images instead of broken links.
- **Soft (start against stub/fixture):** ./M11-events-feature.md's `getEventBySlug(slug)` — until M11's event-branding surface lands, resolve the slug against a single hardcoded fixture event row (**`src/shared/fixtures/lanes/ws-e/event.ts`** — lane-local and WS-E-owned, outside M02's frozen Phase-0 `fixtures/*.ts` set — matching the seed's known slug/timezone/name) so page shells and the day-tab/timezone-label logic can be built and demoed immediately; swap the one import once M11 is confirmed (it lands Sat PM, well before this module's Sunday start — likely no real stub period needed, but don't block on it if M11 is running late).

## Provides (interfaces others consume)
```ts
// src/features/embeds/index.ts
export function getPublishedSchedule(eventSlug: string): Promise<PublishedScheduleDTO | null>;
export function getPublishedSpeakers(eventSlug: string): Promise<PublishedSpeakersDTO | null>;
// null = unknown/deleted slug → caller renders notFound() / branded 404, never a crash
```
Verbatim from PLAN.md §4 M32 (contract stubs land Phase 0, real here). **The four DTOs — `PublishedSessionDTO`, `PublishedScheduleDTO`, `PublishedSpeakerDTO`, `PublishedSpeakersDTO` — are imported from `@/shared/contracts/session.ts`.** [M02](./M02-shared-contracts.md) §4 carries this module's shapes verbatim (they were derived here from `published_sessions_v`/`published_speakers_v`'s columns plus the analysis doc's UI requirements, and contracts adopted them). **Do not redeclare them here**: ./M33-embed-shells.md and WS-F's M40 both consume the same types, and `PublishedScheduleDTO` in particular is **flat** — `{event, days: string[], sessions: PublishedSessionDTO[]}` — not nested day groups. M40 re-groups the flat list by `dayKey` for its JSON response; that grouping is the **API's own** output DTO, not a second read path.
Consumed by:
- ./M33-embed-shells.md — imports `getPublishedSchedule`/`getPublishedSpeakers` and the `schedule-view.tsx`/`speaker-gallery-view.tsx` components directly, wrapping them in a bare shell instead of `public-shell.tsx`. (Per the analysis doc's own simplification: "one component tree, two shells.")
- WS-F's M40 (Public API) — thin JSON wrappers over these same two functions; zero drift, zero second leak path.
- WS-F's M39 (Airtable, dashed) — the Sessions/Speakers Airtable tables source from the same published-data contract.

## Step-by-step implementation

1. **Contract-first slice — ship this SATURDAY PM, not Sunday.** Write `getPublishedSchedule`/`getPublishedSpeakers` in `server/public-queries.ts` as typed stubs returning a small hand-written fixture object matching the contracts DTOs, exported from `index.ts`/`index.client.ts` immediately. Build `public-shell.tsx` (header: event name/logo placeholder + accent color CSS var, nav tabs Schedule/Speakers, footer) and stub page files that render the shell with placeholder content. **Done when:** `/e/<seed-slug>/schedule` and `/e/<seed-slug>/speakers` both return 200 with the shell and fixture content — this alone lets ./M33-embed-shells.md and WS-F's M40 start against a stable shape a **day** before the real queries land, and it de-risks the one module with no fallback by putting something demoable on the deployed preview at the Sat-night checkpoint.

2. **`getPublishedSchedule` — real implementation.** Resolve `eventSlug` → event row (via M11's `getEventBySlug`, or the fixture per the soft dependency above) → `notFound()`-equivalent `null` return on no match. Query `published_sessions_v WHERE event_id = $eventId` (already filters `status='published' AND starts_at IS NOT NULL` — this view IS the draft-leak firewall, do not add or trust any other filter for that job), joined to nothing further for track/room/format (the view already denormalizes those names/colors). Compute `dayKey` per row server-side via `eventDayKey(startsAt, event.timezone)` — never let the client re-derive day buckets from raw UTC. **Speaker bridge** (the one place this module touches a raw table, deliberately safe by construction): also query `published_speakers_v WHERE event_id = $eventId` to get the trusted, confirmation-filtered speaker id set, then `SELECT session_id, contact_id FROM session_speakers WHERE session_id = ANY($publishedSessionIds) AND contact_id = ANY($publishedSpeakerIds)` — restricting the junction-table read to two id sets that are *both* already leak-filtered means this bridge query cannot surface a draft session's speaker or an unconfirmed speaker's identity, even though `session_speakers` itself carries no status column to filter on directly. Assemble `speakers[]` per session from this bridge + the speaker rows' `name`/`headshotUrl` (built as `/f/${headshotFileId}` — no signing, M07's public route is immutable-cached). Sort `sessions` by `startsAt`; `days` = the sorted distinct `dayKey`s present. **Done when:** a PGlite fixture with 1 draft + 1 published + 1 published-but-only-unconfirmed-speaker session returns exactly the published one, and that session's `speakers` array is empty (not erroring) when its sole speaker is unconfirmed.

3. **`getPublishedSpeakers` — real implementation.** Query `published_speakers_v WHERE event_id = $eventId` directly (already filters `confirmation_status='confirmed'` AND session status via its own join — no extra filtering needed here either). For each speaker's `sessions[]`, reuse the same safe bridge pattern from Step 2 (or share one internal helper function between both exports to avoid writing the bridge query twice — fine, it's the same file). Build `headshotUrl` the same way. **Done when:** an admin-declined speaker on an otherwise-published session is absent from the returned `speakers` array entirely (resolution #15's leakage test).

4. **`schedule-view.tsx` — the itinerary.** Day tabs (one per `days[]` entry, labeled via `formatInZone` — e.g. "Tue, Oct 13"), a persistent "All times {zone label}" banner (e.g. "All times PDT" — computed once from the event's timezone at the top of the page, matching the wf2025 reference and the brief's deadline-banner precedent), time-ordered session rows within the selected day (time range, title, track color badge, room name via `<Dash>` if null, speaker name chips with small headshot avatars — initials-circle placeholder when `headshotUrl` is null), a search input (client-side substring filter on title + speaker names — this dataset is small, no need for server round-trips) and a track filter (chip row, multi-select or single-select is fine — client-side filter over the already-fetched `sessions` array). Clicking a row expands `session-detail.tsx` inline (accordion): full `descriptionHtml` via `<RichTextView>` (the ONLY `dangerouslySetInnerHTML` site in the repo — CI greps for this, resolution #2) + full speaker list with headshot, name, and a link to `?speaker=<contactId>` on the Speakers page. **`?session=<id-or-slug>` deep link**: the page reads `searchParams.session` server-side and passes an `initialExpandedSessionId` prop; if it doesn't match any session in the fetched set (deleted/unpublished since the link was shared), the view degrades to the plain unexpanded list — never a 500 or a broken accordion state.

5. **`speaker-gallery-view.tsx` — the card grid.** Responsive grid (`grid-cols-2` on phone up through `grid-cols-4`+ on desktop, Tailwind), each card: headshot (or initials-circle placeholder), name, job title, company (`<Dash>` for any missing field — the seed deliberately has speakers with missing bio/headshot). Click → `speaker-detail.tsx` (bio via `<RichTextView>`, links row for LinkedIn/Twitter/website with `<Dash>` fallback, "Their sessions" list linking back to `?session=<id>` on the Schedule page). **`?speaker=<contactId>` deep link**: same degrade-gracefully rule as Step 4 — an unknown/no-longer-published speaker id falls back to the plain gallery grid (agenda-embeds.md edge case #19), never an error page.

6. **`public-shell.tsx` + `layout.tsx`.** Shell reads the event's branding (name, accent color as a CSS custom property applied to the route group's root, per app-architecture's "one accent CSS variable per event, light mode only" convention) and renders a simple two-tab nav (Schedule / Speakers) + a small footer credit line (own-project attribution, not "Powered by Sessionboard" — this is our own product now). `layout.tsx` at `(public)/e/[slug]/` wraps both pages in this shell so `schedule-view.tsx`/`speaker-gallery-view.tsx` themselves stay chrome-agnostic (no header/nav baked into them) — this is the exact seam ./M33-embed-shells.md needs to bypass the shell entirely for the bare-embed variant.

7. **Caching.** Per PLAN.md §2's caching matrix, these are the canonical "public read-only, s-maxage=60" surfaces. Check `DECISIONS.md` for M01's Fri-night ISR spike (S1/V2) outcome before writing this: if ISR-via-`revalidate` was confirmed working on the deployed OpenNext/Workers artifact, set `export const revalidate = 60` on both page files; if the spike fell back to force-dynamic + a `withEdgeCache`-style Cache-API wrapper, follow that established pattern instead (do not re-litigate the spike decision here — just apply it). Either way the observable contract is the same and is what's tested: an organizer's session edit is visible on this page within 60 seconds, never longer, never permanently stale past that window even under sustained traffic.

## Guardrails
- **This is the one WS-E module the plan explicitly has no fallback for** (§9's cut lines touch the embed *configurator* and the auto-resize script, never these two pages). Treat Sunday as a hard ship date for this module specifically, ahead of ./M30-day-grid-dnd.md even though M30 is listed earlier in the module numbering.
- **Draft-leak-proof by construction, not by care**: every read in this module goes through `published_sessions_v`/`published_speakers_v`; the one raw-table touch (`session_speakers` in the bridge) is safe only because *both* sides of its `WHERE ... = ANY(...)` filter come from ids already pulled out of the trusted views in the same request. Do not add a second query path anywhere in this feature that reads `sessions`/`contacts` directly — if a future page needs something the views don't expose, extend the view (architect-owned, M03) rather than bypassing it.
- **Timezone**: `eventDayKey`/`formatInZone` from `time.ts` for every date computation — this is the module where a UTC-day-binning bug would be most visible to judges (a 9pm-Pacific session showing up under the wrong day tab). The "All times {zone}" banner must always show the *event's* timezone, never the visitor's browser timezone.
- **Rich text**: `descriptionHtml`/`bioHtml` render only via `<RichTextView>` (M05b) — never a raw string interpolation, never a second `dangerouslySetInnerHTML`. The seed's `<img onerror>` XSS probe is expected to appear inert on this exact page; if it ever fires here, it's the most visible possible failure (a public page, framed inside third-party sites via M33) — treat any alert as a stop-ship bug.
- **Nullable rendering**: room/track/format/job title/company/headshot/bio/social links are all nullable in the schema — `<Dash>` or an initials-placeholder everywhere, never `undefined` leaking into the DOM. The seed deliberately ships speakers with missing bio/headshot specifically to catch this.
- **Empty states**: an event with zero published sessions must show "Schedule coming soon" (matching the CMS > Embeds preview screenshot's own empty state), not a blank panel; zero confirmed speakers likewise gets a designed empty grid.
- **Mobile-first is the actual bar**, not a nice-to-have — the brief cites `wf2025.ai.engineer/schedule` by name and the minimum-bar walkthrough explicitly includes viewing this page "framed inside another site" on presumably a laptop-sized iframe *and* directly on a phone; test both.
- **Do not bake the site chrome into `schedule-view.tsx`/`speaker-gallery-view.tsx`** — keeping them chrome-agnostic (Step 6) is what lets M33 reuse them verbatim for the bare embed shell instead of duplicating the view logic.
