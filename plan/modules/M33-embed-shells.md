## Objective
The literal embeddable deliverable: `/embed/[slug]/schedule` and `/embed/[slug]/speakers`, bare-shell variants of ./M32-public-schedule-gallery.md's pages that render inside a third-party site's iframe, plus a copy-paste snippet with auto-resize and a minimal admin screen with an enable/disable kill switch. When done: pasting the iframe snippet into any external HTML page shows a live, auto-updating schedule or gallery, and turning the toggle off blanks it without breaking the host page.

## Dependencies
- **Hard (blocks start):** ./M32-public-schedule-gallery.md — `getPublishedSchedule`/`getPublishedSpeakers` and the chrome-agnostic `schedule-view.tsx`/`speaker-gallery-view.tsx` components, complete and confirmed working on the deployed preview (this module reuses that component tree verbatim — it does not fork or reimplement the schedule/gallery rendering). ./M03-db-schema-migrations.md — `embeds` table migrated.
- **Soft (start against stub/fixture):** none needed — M32 is a solid, same-workstream dependency finished the day before this module starts.

## Step-by-step implementation

1. **Contract-first slice.** Write `isEmbedEnabled`/`getOrCreateEmbedConfig`/`updateEmbedConfig` as thin real implementations immediately (they're simple enough that a stub phase isn't worth it — see Step 2) and the two bare-shell page files rendering M32's components directly with a hardcoded-enabled assumption. **Done when:** `/embed/<seed-slug>/schedule` renders the same content as `/e/<seed-slug>/schedule` minus the site chrome.

2. **`server/config-queries.ts` / `config-mutations.ts`.** `embeds` has **no unique constraint on `(event_id, content_type)`** in the schema (it's a general multi-content-type table; this module only ever uses two of its five enum values, per the deliberate cut of the full configurator). `getOrCreateEmbedConfig`: `SELECT * FROM embeds WHERE event_id = $eventId AND content_type = $contentType ORDER BY created_at LIMIT 1`; if none, `INSERT ... RETURNING *`. This has a benign check-then-insert race (two admins opening the settings page simultaneously for the first time could create two rows) — acceptable for a single-admin hackathon demo; document it as a known, accepted limitation rather than building distributed-lock machinery for it. `isEmbedEnabled` is the same `SELECT` without the insert — absence of a row means "never configured, still enabled" (the public route must work before any admin ever visits the embeds settings page). `updateEmbedConfig` is a plain guarded-by-id `UPDATE ... WHERE id = $embedId AND event_id = $eventId RETURNING *` — no CAS/`row_version` needed here (this table has none, and it's a low-contention single-owner settings surface, the R11 "simple row saves may last-write-wins" exception applies). **Done when:** creating, reading, and toggling a config row round-trips in a PGlite test; a never-configured event still serves both embed types as enabled.

3. **Bare embed pages.** `(embed)/embed/[slug]/schedule/page.tsx` and `.../speakers/page.tsx`: resolve the event, call `isEmbedEnabled(eventId, 'schedule_itinerary' | 'speaker_gallery')`. If disabled: render a small centered "This schedule/gallery is not currently available." message inside `embed-bare-shell.tsx` — **return HTTP 200, not 404** (a live host page's iframe should show a calm inert message, not a browser error page, when an organizer flips the kill switch; the point is that no data leaks and the frame doesn't visually break the host site). If enabled: fetch via M32's `getPublishedSchedule`/`getPublishedSpeakers` and render `<ScheduleView .../>`/`<SpeakerGalleryView .../>` (the exact same components M32 built) inside `embed-bare-shell.tsx` — no `public-shell.tsx` wrapper, no nav, no site header. Read `?accent=`/`?theme=`/`?showHeader=` query params (the ones the admin-page-generated snippet embeds — see Step 5) and apply them at the bare-shell wrapper only: a CSS custom property (`--sb-accent`) on the shell's root div, a `data-embed-theme="dark"` attribute, and conditionally rendering a one-line header bar with the event name when `showHeader=1`. **This module does not deep-restyle M32's internal track/status colors** — that's the full Style/Filters/Field Options configurator, explicitly cut first per §9 #3; keep the ambition here to these three cosmetic knobs only. **Done when:** the disabled state renders inert-but-200; the enabled state matches M32's content pixel-for-pixel apart from the missing chrome and the three optional style knobs.

4. **`embed-bare-shell.tsx` — the auto-resize half.** On mount (and on every `ResizeObserver` callback on the shell's root element), `window.parent.postMessage({ type: 'sb:height', height }, '*')`. `*` as the target origin is deliberate and correct here — the whole point of an embed is that the parent origin is unknown and unconstrained (that's what `frame-ancestors *` already declares); do not tighten this to a specific origin, it would silently break the feature for every host site except one hardcoded during testing.

5. **`public/embed.js` — the script-tag snippet's injector, ~30 lines, zero dependencies.** Reads its own `<script>` tag's `data-*` attributes (event slug, content type, optional accent/theme/showHeader), creates an `<iframe>` pointed at `/embed/{slug}/{type}?accent=...&theme=...&showHeader=...`, sets `style="width:100%;border:0"` and an initial generous `min-height` (e.g. `600px`) so there's no zero-height flash before the first resize message arrives, inserts it into the host page at the script tag's position (standard "replace self with content" pattern), and listens for `message` events with `event.data.type === 'sb:height'` from that specific iframe's `contentWindow`, setting `iframe.style.height = `${height}px``. This file is a genuinely static asset (served by Workers Assets, not through a route handler) — no build step, plain browser JS, ES5-safe if easy.

6. **`embed-admin-panel.tsx` + admin route.** For each of the two canonical content types, a card showing: Enabled toggle (calls `updateEmbedConfig`), the three style controls (accent color input, light/dark segmented control, show-header checkbox — each change stages local state, one "Save" persists via `updateEmbedConfig`), two "Copy" buttons producing (a) the **plain iframe snippet** (zero-JS, always works, generous `min-height` and internal scroll — the recommended default) and (b) the **script-tag snippet** (`<div id="sb-embed-…"></div><script src=".../embed.js" data-event="{slug}" data-type="schedule" async></script>` — the auto-resizing variant), and a "View embed ↗" link opening the real `/embed/{slug}/{type}` URL in a new tab as the preview (no live in-page iframe preview — deliberately simple, matching the cut-first NICE-tier configurator's absence). Route: `src/app/(admin)/events/[eventId]/embeds/page.tsx`, RSC calling `getOrCreateEmbedConfig` for both types server-side, hydrating the panel. **Done when:** copying either snippet and pasting it into a scratch HTML file produces a working embed.

7. **API routes.** `src/app/api/internal/embeds/route.ts` (GET = list both configs for the event), `.../[embedId]/route.ts` (PATCH = `updateEmbedConfig`), both via `defineHandler({ auth: adminAuth(), ... })` (the guard **factory call** from `@/features/auth`, per M04 §8).

- `pnpm vitest run src/features/embeds` (config CRUD PGlite tests).

## Guardrails
- **`frame-ancestors *` must stay scoped to `/embed/:path*` only** — never let it leak onto `/e/[slug]/...` (M32's canonical pages, which should keep standard framing protection) or anywhere in `(admin)`/`(portal)`. This header rule is configured by ./M01-scaffold-ci-deploy.md in `next.config.ts`; this module does not need to (and should not) touch that file — it only needs its routes to physically live under the `/embed/` path segment so the existing matcher applies, and to verify via curl that it actually survived OpenNext's Workers adapter. **NEEDS-VERIFY dependency (platform-integrations.md V8):** if the curl check in Step 3 of Acceptance criteria fails on the deployed artifact, check `DECISIONS.md` for the pre-decided fallback — setting the CSP header directly in a route-handler response (rather than relying on `next.config.ts`) — and restructure the two bare-embed pages as route handlers returning rendered HTML with an explicit header if that fallback was taken.
- **Disabled must gate serving, not just hide a UI affordance** (agenda-embeds.md edge case #8) — the check happens server-side in the page component before any data fetch, not as a client-side conditional after the fact; a disabled embed must never even call `getPublishedSchedule`/`getPublishedSpeakers`.
- **No forked schedule/gallery logic** — this module imports M32's view components as-is. If a bare-shell-specific need arises that seems to require editing `schedule-view.tsx` itself, that's a signal the component wasn't chrome-agnostic enough; solve it at the wrapper level (`embed-bare-shell.tsx`) or flag it back to how M32 was built, never duplicate the component.
- **`postMessage` target origin `*` is intentional**, not a security shortcut to fix later — an embed by definition doesn't know its host origin in advance. This is not a XSS/data leak, since the payload is only a height number.
- **Caching**: bare embed pages inherit the exact same 60s auto-update tier as M32's canonical pages (same underlying data functions) — do not add a separate, longer cache for the embed variant; "auto-update within a minute" is the brief's requirement and must hold for both the direct page and the embedded one identically.
- **`embed.js` is genuinely static** — no server round trip to generate it, no template variables baked in at build time beyond what's already knowable (it reads everything it needs from the consuming page's own `data-*` attributes at runtime). Keep it dependency-free so it never becomes a bundle-size or CORS concern.
